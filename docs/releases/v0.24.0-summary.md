# PlayWeld 0.24.0 testing prerelease

This build packages the SDK verification and developer-hook work merged after 0.23.0. The discussed changes were already on main; no unrelated dependency PRs were merged for this release.

- Plugin SDK conformance now exercises 20 cases covering initialization and settings retry, protocol/context validation, access modes, unknown methods/tools, typed handler errors and stdout-safe logging. Integration guidance was corrected to match current source. This is verification of existing behavior, not a new SDK protocol or community-plugin certification.
- Entire developer configuration includes a shell-safe Windows Codex SessionStart launcher and a Node-based advisory Claude Brain launcher. The merged records preserve isolated Windows shell/CLI fixture results and the known Entire template-recognition warning.
- Tool-broker audit verification now explicitly covers startup Knowledge indexing alongside filesystem calls, retaining exact filesystem audit assertions without raising timeouts.
- Planning and evidence records are reconciled with the completed slices. Proposed project tasks remain proposals; this release does not implement them.

Entire hook configuration and Windows fixtures do **not** establish trusted end-to-end transcript capture, Brain indexing/context injection, hosted Entire access, Unix Claude session acceptance or reviewer approval. No signing key, credential or security-setting change was made by release preparation.

Windows x64 NSIS and Linux x64 AppImage/DEB packages are provided for manual testing. See `gamecrafter-release.json` and `SHA256SUMS.txt` for source provenance, compatibility and hashes. Signing status is stated in the manifest; checksums establish integrity, not publisher identity. Windows Authenticode publisher signing is not claimed.

The complete version notes are attached as `PlayWeld-0.24.0-release-notes.md` and retained in source with the full changelog. This is a **testing prerelease**, excluded from stable automatic updates. Installed upgrade/uninstall/rollback, ordinary-profile preservation on this build and broader live provider/engine/accessibility acceptance remain separate qualifications.
