## Remaining work and issue scope

All discovered application problems and incomplete implementation areas remain eligible for repair under the user's instruction. This first documentation pass does not complete the whole target platform. It preserves existing gaps instead of giving readers instructions for unavailable features. The external IDE MCP server, native Theia AI model adapter, broad canon reconciliation, paid-provider acceptance, and installer/rollback acceptance remain documented in the existing status/plan. They need implementation or external integration evidence beyond this tutorial.

The [current combined capture report](images/lantern-workflows-2026-10-04/capture-report.json) records actual UI connection at negotiated revision 2025-11-25, explicit tool classification, broker invocation and disconnect. It also records synthetic asset generation/review/import using a local metadata-only GLB fixture, path rejection and corrected import; no paid provider or usable geometry claim.

The original timer prompt remains illustrative. The later agent fixture creates only a synthetic document; it does not implement a timer or establish paid-model quality. Paid asset generation/native geometry acceptance, a new live external MCP endpoint, graphical Lantern Workshop gameplay, plugin tool execution on a supported host, remote restoration, and installer rollback still require explicit evidence. Windows plugin isolation is a real missing capability, retained as a gap rather than bypassed for screenshots.

Future documentation additions should pair a reproducible action, prerequisites, expected result, screenshot/artifact, exact observed failure if any, fix, and rerun evidence. Keep all outstanding failures visible until actually repaired; use permanent work records for fixes and keep implementation status in its designated documents.
