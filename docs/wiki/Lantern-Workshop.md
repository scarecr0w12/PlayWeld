# Lantern Workshop

This disposable Godot example teaches workspace setup, discussion and search without risking production data or requiring paid generation.

## Prepare

For practice from a built source checkout, choose separate profile and editor preference directories before launch:

```powershell
$env:GAMECRAFTER_PROFILE_DIR = 'E:\PlayWeldTutorial\profile'
$env:THEIA_CONFIG_DIR = 'E:\PlayWeldTutorial\theia'
npm run start -w @gamecrafter/control-room
```

Use host-native paths appropriate to your machine. These variables affect new processes; they do not move a running service. See [source setup](https://github.com/scarecr0w12/PlayWeld/wiki/Development-and-Contributing).

Create **Lantern Workshop**, choose **Godot** and a disposable parent directory, then open it. Copy only docs/ and game/ contents from the [checked-in example](https://github.com/scarecr0w12/PlayWeld/blob/main/docs/examples/lantern-workshop/README.md) into the new Project; preserve its generated manifest and operational state. The [walkthrough](https://github.com/scarecr0w12/PlayWeld/blob/main/docs/WORKED_TUTORIAL.md) owns exact copy commands and screenshots.

## Practice and verify

1. Read docs/DESIGN.md and inspect native files.
2. Create a Discussion Board thread about collection/reset rules; save and reopen it.
3. Choose Knowledge **Index status > Reconcile** and wait for indexing.
4. Search **Lexical**, source **docs**, for **lantern**. Inspect the docs/DESIGN.md citation.
5. With your own configured model, optionally ask a small **Chat** question and inspect its persisted reply. Remote requests may cost money.
6. Install the appropriate Godot executable before checking the game itself.

Screenshot captures use a temporary scripted localhost provider. Its endpoint is not reusable, and scripted answers do not demonstrate reasoning. The sample timer prompt is an instruction example, not evidence it ran. Agent submission and paid generation require deliberate configuration and review.
